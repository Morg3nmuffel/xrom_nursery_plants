# Питомник · Панель администратора и кабинет сотрудника

React-приложение для трёх микросервисов из соседней папки `backend`. В поставке есть исходники и готовая сборка. Для запуска нужен Node.js 24.4 или новее.

## Локальная демонстрация

На macOS дважды нажмите **Открыть демоверсию.command** в папке `frontend`. На любой платформе можно открыть терминал в этой папке и выполнить:

```sh
node demo.mjs
```

Задайте пароль для этого запуска в терминале. Откройте **http://127.0.0.1:8790/** и войдите с логином `admin` и заданным паролем. Учебные остатки и задания сохраняются в `frontend/demo-data`. При следующем запуске пароль задаётся заново. Остановка в терминале выполняется сочетанием Ctrl+C. Для автоматизированного локального запуска пароль можно передать в `NURSERY_DEMO_PASSWORD`.

Демонстрация запускает три отдельных процесса на локальных портах 18787–18789. В примере пять сотрудников и пять исходных партий.

## Подключение к рабочему backend

1. Запустите три сервиса из соседней папки по её инструкции. Укажите одинаковые `ADMIN_USERNAME` и `ADMIN_PASSWORD` для каждого процесса, включая сервис задач. Для боевых данных используйте рабочие SQLite и рабочие реквизиты администратора.
2. На macOS дважды нажмите **Открыть питомник.command** в папке `frontend`. На любой платформе можно выполнить `node server.mjs` из этой папки. По умолчанию веб-сервер подключится к учёту на 8787, задачам на 8788 и складу на 8789.
3. Откройте **http://127.0.0.1:8790/**. Для размещения на сервере завершайте HTTPS на обратном прокси, сохраняйте исходный заголовок Host и задайте `WEB_SECURE_COOKIE=1`. Публичный трафик направляйте на веб-сервер. Адреса внутренних процессов задаются `WEB_PLANTS_URL`, `WEB_TASKS_URL` и `WEB_STORE_URL`. Адрес и порт веб-сервера задаются `WEB_HOST` и `WEB_PORT`.

Сервер создаёт сессию нужной роли. Административная сессия подключает три API, сессия сотрудника — только сервис задач. В браузер передаётся идентификатор сессии в HttpOnly cookie со сроком до восьми часов. Внутренние токены хранятся в памяти веб-сервера. После выхода или перезапуска веб-сервера требуется новый вход.

## Работа сотрудника

1. Администратор в разделе «Сотрудники» добавляет сотрудника и передаёт ему указанные в форме логин и пароль.
2. На экране входа сотрудник выбирает «Сотрудник» и вводит выданные реквизиты.
3. В «Моих задачах» сотрудник открывает назначенную ему задачу и нажимает «Начать выполнение». Карточка переходит в «В работе».
4. В той же карточке сотрудник нажимает «Завершить работу». В разделе «Готово» отображаются десять последних завершённых задач сотрудника. Более ранние записи сохраняются в SQLite.

## Возможности

- Обзор остатков, стадий и заданий. Данные обновляются каждые 30 секунд и по кнопке «Обновить».
- Поиск партий, регистрация посадки, изменение стадии, количества и места, история партии и удаление посадки из учёта.
- Добавление и удаление сотрудников и задач, фильтр по исполнителю и инструкции по уходу.
- Добавление и удаление карточек растений с условиями ухода, высотой и показателями зимостойкости.
- Остатки расходников, приход, ручное списание, добавление и удаление материалов, нормы посадки, журнал движений и результат автоматических списаний.

## Разработка

React-компоненты находятся в `src`, оформление и локальная фотография теплицы — в `public`. После изменения JSX выполните в папке `frontend`:

```sh
pnpm install --frozen-lockfile
pnpm run build
```

Сборки страницы входа, административной панели и кабинета сотрудника обслуживает `server.mjs`. Запустите `node --test` из корня репозитория для проверки веб-сервера и микросервисов.
