# Питомник · Магазин, кабинет сотрудника и панель администратора

React-приложение для трёх микросервисов из соседней папки `backend`. В поставке есть исходники и готовая сборка. Для запуска нужен Node.js 24.4 или новее.

## Локальная демонстрация

На macOS дважды нажмите **Открыть демоверсию.command** в папке `frontend`. На любой платформе можно открыть терминал в этой папке и выполнить:

```sh
node demo.mjs
```

Откройте **http://127.0.0.1:8790/** и войдите с логином `admin` и паролем `demo-admin`. Учебные остатки и задания сохраняются в `frontend/demo-data`. Остановка в терминале выполняется сочетанием Ctrl+C.

Чтобы задать свой пароль для локальной демонстрации, укажите `NURSERY_DEMO_PASSWORD` в файле `frontend/.env.local-admin`. Этот файл исключён из Git. Одноимённая переменная окружения имеет приоритет над файлом.

Демонстрация запускает три отдельных процесса на локальных портах 18787–18789. В примере пять сотрудников, пять исходных партий и девять растений с учебными ценами в витрине. Фикстура витрины добавляется один раз в учебную базу и сохраняет ранее заданные цены.

При первом запуске в учебную базу добавляются по три примера для колонок «В работе» и «Готово» на доске команды. Как и остальные выполненные задачи, примеры в колонке «Готово» показываются на доске администратора в день завершения.

### Три роли в одном браузере

Откройте в отдельных вкладках `/admin/`, `/employee/` и `/customer/` на адресе сайта. Каждая ссылка открывает форму нужной роли или её кабинет, если вход уже выполнен. Сайт хранит отдельную сессию для каждой роли. Выход из одного кабинета оставляет два других доступными.

## Подключение к рабочему backend

1. Запустите три сервиса из соседней папки по её инструкции. Укажите одинаковые `ADMIN_USERNAME` и `ADMIN_PASSWORD` для каждого процесса, включая сервис задач. Для боевых данных используйте рабочие SQLite и рабочие реквизиты администратора.
2. На macOS дважды нажмите **Открыть питомник.command** в папке `frontend`. На любой платформе можно выполнить `node server.mjs` из этой папки. По умолчанию веб-сервер подключится к учёту на 8787, задачам на 8788 и складу на 8789.
3. Откройте **http://127.0.0.1:8790/**. Для размещения на сервере завершайте HTTPS на обратном прокси, сохраняйте исходный заголовок Host и задайте `WEB_SECURE_COOKIE=1`. Публичный трафик направляйте на веб-сервер. Адреса внутренних процессов задаются `WEB_PLANTS_URL`, `WEB_TASKS_URL` и `WEB_STORE_URL`. Адрес и порт веб-сервера задаются `WEB_HOST` и `WEB_PORT`.

Сервер создаёт сессию нужной роли. Административная сессия подключает три API, сессия сотрудника — только сервис задач. В браузер передаётся идентификатор сессии в HttpOnly cookie со сроком до восьми часов. Внутренние токены хранятся в памяти веб-сервера. После выхода или перезапуска веб-сервера требуется новый вход.

## Работа сотрудника

1. Администратор в разделе «Сотрудники» добавляет сотрудника и передаёт ему указанные в форме логин и пароль.
2. На экране входа сотрудник выбирает «Сотрудник» и вводит выданные реквизиты.
3. В «Моих задачах» сотрудник открывает назначенную ему задачу и нажимает «Начать выполнение». Карточка переходит в «В работе».
4. В той же карточке сотрудник нажимает «Завершить работу». В разделе «Готово» отображаются десять последних завершённых задач сотрудника. Более ранние записи сохраняются в SQLite.

## Магазин и консультации

На экране входа выберите **«Пользователь» → «Создать аккаунт»**. Каталог показывает растения с положительным остатком в партиях «Готово к продаже». Данные о наличии и ценах поступают из учёта. Корзина сохраняется после выхода и перезапуска. Добавление в корзину не резервирует остаток.

В разделе **«Консультант»** можно спросить об уходе, указать условия для подбора или попросить добавить конкретное растение в корзину. Например, «Подберите растение для полутени», затем «Добавь 2 экземпляра первой позиции».

В чате покупателя Enter отправляет сообщение, Shift+Enter добавляет строку.

Когда в справочнике недостаточно сведений, чат передаёт вопрос в **«Вопросы пользователей»**. Администратор видит всю переписку и отвечает прямо в панели. Пока пользователь ждёт ответа, его уточнения поступают в то же обращение. После ответа администратора консультант автоматически возвращается в чат. Если сведений снова не хватит, новое сообщение откроет то же обращение с полной историей.

При сравнении консультант показывает все подтверждённые сведения и отмечает, по каким растениям или параметрам данных не хватает. В чате также можно узнать, что сейчас есть в каталоге, посмотреть свою корзину и сравнить растения из неё. Содержимое корзины берётся из базы текущего пользователя.

## Подключение модели

Скопируйте [`.env.example`](../.env.example) в `.env` в корне проекта и впишите `OPENAI_API_KEY`. Сервис учёта растений читает этот файл при обработке сообщений. Ключ или модель можно поменять без перезапуска. Переменные окружения сервиса имеют приоритет над файлом.

| Переменная | Значение |
| --- | --- |
| `OPENAI_API_KEY` | Ключ OpenAI. При заполнении используется OpenAI Responses API |
| `CONSULTANT_MODEL` | Модель, по умолчанию `gpt-5.4-mini` |
| `CONSULTANT_API_URL` | Дополнительная настройка для другого провайдера. Полный URL Responses или Chat Completions |
| `CONSULTANT_API_KEY` | Ключ другого провайдера, если требуется. Задайте его вместе с `CONSULTANT_API_URL` и моделью |

Модель получает текущий вопрос, до восьми последних сообщений автоматического чата после последнего ответа администратора, идентификаторы выбранных растений и сведения из справочника. Учётные данные и сообщения администратора остаются на сервере. Модель выбирает поля для ответа, условия подбора или позицию корзины. Сервер проверяет выбор и формирует ответ из SQLite. Например, после «Утром светло, после обеда тень» можно уточнить «Хочу что-нибудь хвойное», а после подбора сказать «Я возьму пару экземпляров первого растения».

При недостатке сведений вопрос передаётся администратору. Без ключа или при сбое API встроенные правила обслуживают типовые вопросы и подбор по известным условиям. Файл `.env` исключён из Git.

## Возможности

- Обзор остатков, стадий и заданий. Данные обновляются каждые 30 секунд и по кнопке «Обновить».
- Поиск партий, регистрация посадки, изменение стадии, количества и места, история партии и удаление посадки из учёта.
- Добавление и удаление сотрудников и задач, фильтр по исполнителю и инструкции по уходу.
- Добавление и удаление карточек растений с условиями ухода, высотой и показателями зимостойкости.
- Остатки расходников, приход, ручное списание, добавление и удаление материалов, нормы посадки, журнал движений и результат автоматических списаний.

## Разработка

React-компоненты находятся в `src`, оформление и локальная фотография теплицы — в `public`. После изменения JSX выполните в папке `frontend`:

```sh
pnpm install --frozen-lockfile
pnpm run build
```

Сборки страницы входа, административной панели и кабинета сотрудника обслуживает `server.mjs`. Запустите `node --test` из корня репозитория для проверки веб-сервера и микросервисов.
