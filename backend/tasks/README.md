# Задачи питомника

Микросервис назначает работы сотрудникам по текущим партиям, стадиям роста и карточкам ухода. HTTP API возвращает личный список задач или список всей команды. Начать и завершить задачу может её исполнитель. Статусы и время выполнения сохраняются в SQLite.

## Запуск на пяти демонстрационных партиях

Понадобится Node.js 24.4 или новее. Откройте терминал в папке, где рядом лежат `server.mjs`, `tasks` и `consumables`. Учебная конфигурация общая для трёх процессов. [Запуск всех сервисов](../README.md#запуск-трёх-сервисов)

Скопируйте [шаблон](../examples/demo.env.example) в `examples/demo.env` и заполните параметры запуска.

```sh
node --env-file=examples/demo.env server.mjs seed-demo
node --env-file=examples/demo.env tasks/server.mjs
```

Сервис запустится на `http://127.0.0.1:8788`. Для проверки API используйте логин `anna` и пароль `demo-anna`. [Все учебные учётные записи](../examples/task-employees.json)

## Подключение к учёту

Укажите тот же абсолютный путь `INVENTORY_DB`, что и у [сервиса учёта](../README.md). При первом запуске можно передать JSON с начальными учётными записями. Дальше список команды хранится в таблице `employees` общей базы SQLite, пароли сохраняются в виде хешей с солью. Администратор добавляет и удаляет сотрудников в панели. При следующем запуске повторная загрузка списка из JSON не требуется.

В каталоге [plants.json](../catalog/plants.json) находится предоставленный справочник. При создании SQLite сервис учёта импортирует его в `plant_care`. Для загрузки обновлённого справочника выполните `node server.mjs import-catalog путь/к/plants.json`, задав ту же `INVENTORY_DB`. Изменения видны в открытых задачах по `plant_id`. Запускайте сервис учёта параллельно, если нужно регистрировать партии, проводить продажи или обрабатывать календарь роста.

| Переменная | Значение по умолчанию |
| --- | --- |
| `INVENTORY_DB` | Тот же путь, что у сервиса учёта |
| `TASKS_EMPLOYEES_FILE` | Путь к JSON сотрудников, если он передаётся через окружение |
| `TASKS_HOST` | `127.0.0.1` |
| `TASKS_PORT` | `8788` |
| `TASKS_TIME_ZONE` | `Europe/Moscow` |
| `TASKS_INTERVAL_MS` | `30000` |

## Управление через панель

Раздел «Сотрудники» позволяет добавлять учётные записи и отзывать доступ. Открытые задачи удалённого сотрудника планировщик распределяет между действующими сотрудниками. При отсутствии исполнителей работа ожидает назначения. Имена исполнителей выполненных задач сохраняются в истории.

В разделе «Задачи» можно создать поручение для партии или общую задачу питомника, выбрать срок и исполнителя. Удаление доступно в карточке задачи. Планировщик учитывает удаление автоматического задания до конца текущего рабочего дня.

## Как выдаются задания

- Планировщик запускается при старте и каждые 30 секунд. Для каждой партии с положительным остатком он назначает одну задачу по текущей стадии. Посевы, укоренение, доращивание и товарные партии имеют разные инструкции.
- При наличии карточки ухода задача показывает подходящие выдержки из неё. Частоту полива определяют по состоянию субстрата и карточке. Для двух демонстрационных партий без карточек задаётся осмотр с уточнением ухода у ответственного.
- Следующая задача достаётся сотруднику с наименьшим числом открытых заданий и заданий, выполненных сегодня. При равенстве порядок сотрудников сдвигается каждый день. При пяти новых партиях и нулевой нагрузке каждый получает по одной задаче.
- Просроченная задача остаётся открытой до завершения. Следующее задание для этой партии появляется после дня фактического завершения. В открытых задачах возвращаются текущие количество, место и стадия. Если остаток становится нулевым, задача исключается из списка до появления остатка. Для завершённых задач возвращаются данные на момент закрытия.
- Личный список включает открытые задачи сотрудника и десять последних завершённых задач по времени выполнения. Командный список включает открытые задачи и задачи, завершённые в текущий локальный день. SQLite сохраняет полную историю.

## HTTP API

Административная панель входит через `POST /api/admin/login` c `ADMIN_USERNAME` и `ADMIN_PASSWORD`. С административным Bearer-токеном `GET /api/admin/tasks` возвращает задачи команды и список исполнителей. `POST /api/admin/logout` завершает сеанс. Административные маршруты включаются при заданном `ADMIN_PASSWORD`. Токены сотрудников и администратора проверяются отдельно.

| Запрос | Действие |
| --- | --- |
| `GET /health` | Проверка доступности сервиса и базы |
| `POST /api/tasks/login` | Принимает JSON с `username` и `password`, возвращает `access_token` |
| `GET /api/tasks?scope=mine` | Задачи текущего сотрудника. `mine` используется по умолчанию |
| `GET /api/tasks?scope=team` | Задачи всех сотрудников |
| `POST /api/tasks/{id}/start` | Начинает задачу, повтор сохраняет исходное время начала |
| `POST /api/tasks/{id}/complete` | Закрывает начатую задачу, повтор возвращает ранее сохранённое выполнение |
| `POST /api/tasks/logout` | Завершает сеанс |

Передайте `Authorization: Bearer <access_token>` для получения задач, смены статуса и выхода. Список возвращает `date`, `time_zone`, текущего сотрудника в `employee` и задачи в `items`. У каждой задачи есть `id`, `assignee_id`, `assignee_name`, сведения о партии, инструкции по уходу и один из статусов `todo`, `in_progress` или `done`. Время действий выдаётся в UTC. Даты `date` и `due_on` используют часовой пояс питомника. Для задачи в статусе `todo` вызов `complete` возвращает 409.

### Проверка на демонстрационных данных

В другом терминале получите токен и запросите задачи. Пример для macOS и Linux.

```sh
TASKS_TOKEN=$(curl -fsS http://127.0.0.1:8788/api/tasks/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"anna","password":"demo-anna"}' \
  | node -p 'JSON.parse(require("node:fs").readFileSync(0, "utf8")).access_token')

curl -fsS -H "Authorization: Bearer $TASKS_TOKEN" http://127.0.0.1:8788/api/tasks
```

Возьмите `id` открытой задачи из `items` и передайте его в `POST /api/tasks/{id}/complete`. В ответе будут `status: "done"` и `completed_at`.

Проверки всех сервисов запускаются командой `node --test` из папки с `server.mjs` сервиса растений.
